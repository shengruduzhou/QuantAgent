## 1. 网页调研摘要 / Web research summary

共执行 7 次 search/fetch。要点与本仓库的对照：

1. **奖励函数本身就是超参数，且 DRL 对它极度敏感** —— 「the choice of reward function is a hyperparameter in itself, and the convergence of the model depends upon the preference of the reward function」。
   → 对照：本仓库的 reward 只有一个尺度参数 `reward_scale=100.0` 和一个成本参数 `cost_bps=12.0`，
   形式固定为 value-add，**没有**做过 reward 形式的搜索。这是好事（少一个可过拟合的自由度），
   但也意味着「风险调整」完全不在奖励里（见 §2 缺口）。
   来源：[Portfolio Management using Deep RL (arXiv 2405.01604)](https://arxiv.org/html/2405.01604v1)

2. **DRL 在金融上的主要失效模式是对稳定 regime 的过拟合 + backtest overfitting**，
   「PPO and stochastic policy gradient descent problems are notorious for overfitting」。
   → 对照：仓库的 `PPOTrainingConfig.timesteps` 默认 **5,000,000** 步，
   而 `PITPortfolioEnv` 的一个 episode 长度 = 信号日数（真实面板下量级 10²–10³）。
   这意味着默认配置会把同一段历史**重复跑数千到数万遍**。见 F-RL-05。
   来源：[Diffusion-Augmented RL for Robust Portfolio Optimization (arXiv 2510.07099)](https://arxiv.org/html/2510.07099)

3. **Differential Sharpe Ratio (Moody & Saffell)** —— 在线可增量计算的风险调整奖励，
   O(1) 更新一二阶矩，使 cumulative reward 逼近整段 Sharpe。
   → 对照：本仓库奖励是**纯收益差**，无任何风险项。用户目标是「最高超额」，
   但按 `AGENTS.md` 的验收门槛还要过 max drawdown 闸门 —— **奖励与验收闸门不同构**，
   策略可以在奖励上赢、在闸门上被否。见 F-RL-04。
   来源：[Moody & Saffell, RL for Trading (NeurIPS)](http://papers.neurips.cc/paper/1551-reinforcement-learning-for-trading.pdf)、
   [Risk-Aware RL Reward for Financial Trading (arXiv 2506.04358)](https://arxiv.org/html/2506.04358v1)

4. **QlibRL 框架分层**：`EnvWrapper` = `Simulator` + `StateInterpreter` + `ActionInterpreter` + `Reward`，
   四者有独立基类；奖励从 simulator 状态计算，与观测解耦。
   → 对照：本仓库 `PITPortfolioEnv` 把这四件事**揉在一个类里**，
   `_build_caches` 同时负责数据校验、执行约束推导、奖励收益预计算和观测特征构造（~280 行单函数）。
   这不是正确性缺陷，但让「换奖励」必须改环境。见 F-RL-06（P2）。
   来源：[QlibRL framework](https://qlib.readthedocs.io/en/latest/component/rl/framework.html)、
   [QlibRL overall](https://qlib.readthedocs.io/en/latest/component/rl/overall.html)

5. **执行类 RL 的奖励通常锚在 implementation shortfall / AC utility 的相对改善**上，
   而非绝对收益 —— 与本仓库「value-add vs 被动账本」的相对化思路一致。
   → 这一点上仓库的设计是**符合文献主流且优于绝对收益奖励**的：相对化天然消掉了 beta，
   直接对应用户的「超额」目标，也堵死了「牛市里什么都不做也赢」的 env-flat 陷阱。
   来源：[TT-DAC-PS: Optimal Trade Execution (arXiv 2606.08379)](https://arxiv.org/pdf/2606.08379)

6. **A 股 T+1 的正确处理是 "mask-first"** —— 「every computational operator explicitly accepting and
   propagating a Boolean tradability mask... rather than allowing invalid actions and penalizing them afterward」。
   → 对照：本仓库用的正是 mask-first（`_apply_execution_constraints` 在**算奖励之前**裁剪权重），
   **不是**事后惩罚。这是正确做法。见 §3。
   来源：[ML-Enhanced Multi-Factor Quantitative Trading (arXiv 2507.07107)](https://arxiv.org/pdf/2507.07107)

7. **AKQuant** 强调「模型在 bar *t* 训练，直到 bar *t+1* 才执行预测，这个自然延迟阻止同 bar 前视」，
   并把 full-dataset 预处理（如 StandardScaler）列为泄漏源。
   → 对照：`PITPortfolioEnv` 的 alpha z-score 是**逐信号日横截面**标准化
   （`pit_portfolio_env.py:275-280`），**不是**全样本标准化 —— 这一点是对的，无泄漏。
   来源：[AKQuant 机器学习](https://akquant.akfamily.xyz/advanced/ml/)

## 2. 奖励函数的数学定义 / What the reward actually is

唯一被训练器使用的环境是 `PITPortfolioEnv`（`train_ppo.py:30,119`）。
逐行读 `src/quantagent/rl/pit_portfolio_env.py:401-491`：

### 2.1 公式

记信号日 $T$，执行日 $T{+}1$，奖励结束日 $T{+}2$（均为**面板里的会话**，见 F-RL-01）。

**动作**（`pit_portfolio_env.py:405-423`）：$a \in [-1,1]^{n+1}$，前 $n$ 维是逐名倾斜，第 $n{+}1$ 维是总仓位倾斜。

$$w^{\text{raw}}_i = b_i \cdot (1 + \lambda_{\text{tilt}} a_i), \quad \lambda_{\text{tilt}} = 0.8$$
$$w^{\text{raw}}_i \leftarrow \max(w^{\text{raw}}_i, 0) \cdot \mathbb{1}[i \in \text{book}]$$
$$G = \mathrm{clip}\Big(\textstyle\sum_i b_i \cdot (1 + \lambda_{\text{cash}} a_{n+1}),\ G_{\min}, G_{\max}\Big),\quad \lambda_{\text{cash}}=0.3,\ G_{\min}=0.5,\ G_{\max}=1.0$$
$$w \leftarrow w^{\text{raw}} \cdot G / \textstyle\sum_i w^{\text{raw}}_i$$

其中 $b$ = 被动账本权重（`passive_w[t]`，调用方传入的 `book_weights`）。

**执行约束**（`pit_portfolio_env.py:438-451, 662-674`）——在算奖励**之前**施加，mask-first：

$$w_i \leftarrow \begin{cases}
w^{\text{prev}}_i & \text{suspended}(i, T{+}1)\\
\min(w_i, w^{\text{prev}}_i) & \text{limit-up}(i, T{+}1)\\
\max(w_i, w^{\text{prev}}_i) & \text{limit-down}(i, T{+}1)
\end{cases}$$

**同一约束也施加在被动账本上** $w^{b}$（`:445-451`）——这是关键，保证对照是同口径的。

**收益**（`pit_portfolio_env.py:321, 453-455`）：

$$r_i = \frac{\text{close}_i(T{+}2)}{\text{close}_i(T{+}1)} - 1$$

**成本**（`:460-463`）：$c = \tau \cdot \text{bps}/10^4$，$\tau = \sum_i |w_i(t) - w_i(t{-}1)|$（按 symbol 求并集，`_sym_turnover:723-725`），$\text{bps}=12$。

**最终奖励**（`:465-468`）：

$$\boxed{\;R_t = \kappa \cdot \Big[\big(\langle w, r\rangle - c_{\text{policy}}\big) - \big(\langle w^{b}, r\rangle - c_{\text{passive}}\big)\Big],\quad \kappa = 100\;}$$

### 2.2 它奖励的是什么 —— 逐项回答

| 维度 | 结论 | 证据 |
|---|---|---|
| 绝对收益？ | **否** | 奖励里减去了 `net_passive`（`:467`） |
| 超额收益？ | **是** —— 但基准是**调用方传入的被动账本**，不是指数、不是等权全 A | `:466-467`；`train_ppo.py:91` `book_weights` 是必填 keyword-only |
| 风险调整后收益？ | **否** | 无方差项、无 Sharpe 项、无 drawdown 项。逐 step 线性于收益 |
| 回撤惩罚？ | **否** | `PITPortfolioEnvConfig`（`:43-52`）无任何 drawdown 字段；`step` 里维护 `_nav` 但**从不进入 reward**（`:470` 只是记账） |
| 换手惩罚？ | **只经成本**，12 bps 线性 | `:460-463`。且因为是差分，policy 与 passive 的换手**互相抵消** |
| 成本惩罚？ | **是**，但双边同口径 | 同上 |

**对比：已被弃用的 `PortfolioEnv`（`portfolio_env.py:155`）奖励反而更丰富**：
```
reward = pnl - benchmark_excess_weight*benchmark - cost - dd_penalty - kill_penalty
```
它**有**回撤惩罚（`drawdown_lambda=2.0`, `drawdown_limit=0.20`）和 kill-switch 惩罚（`kill_switch_drawdown=0.30`）。
即**在把奖励时钟修对的同时，风险惩罚项被一并丢掉了**，且没有任何文档记录这个取舍。见 F-RL-04。

### 2.3 「零动作 = 零奖励」的构造性保证与它的漏洞

$a = 0 \Rightarrow w^{\text{raw}} = b \Rightarrow$ 若 $\sum b_i \in [G_{\min}, G_{\max}]$ 则 $G = \sum b_i$，
故 $w = b$，两条约束路径相同，$R = 0$ **恰好**。这是本环境最重要的设计优点，直接免疫 env-flat。

**但存在漏洞（F-RL-03, P2）**：若 $\sum_i b_i < G_{\min} = 0.5$（被动账本本身是低仓位的），
则 `:419-423` 的 `clip` 会把 $G$ 抬到 0.5，$w = b \cdot (0.5/\sum b) \ne b$，
**零动作不再是零奖励** —— 环境替 agent 做了一次加杠杆决策并把结果计入 value-add。
