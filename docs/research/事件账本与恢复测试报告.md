# 事件账本与恢复测试报告

- **生成时间**：2026-07-29（UTC）
- **源提交**：`17ada19996fc5f1fceae06bac60ff5ab05d4a922`
- **实现**：`src/quantagent/paper/ledger.py`、`recovery.py`

## 1. 设计原则：状态是推导出来的，不是存下来的

现金、持仓、在途订单、成交、已实现/未实现盈亏、风控状态、Kill Switch 状态
**全部由重放事件账本得到**，没有任何一项作为可变状态单独保存。

这不是风格选择，而是让"恢复"这件事**可被验证**的前提：如果状态另存一份快照，
恢复成功只能证明快照可读，**不能证明它与真实发生过的事情一致**。

## 2. 事件类型（20 种）

`SIGNAL_CREATED`、`TARGET_GENERATED`、`RISK_APPROVED`、`RISK_REJECTED`、
`ORDER_CREATED`、`ORDER_ACCEPTED`、`ORDER_REJECTED`、`ORDER_PARTIALLY_FILLED`、
`ORDER_FILLED`、`ORDER_CANCEL_REQUESTED`、`ORDER_CANCELLED`、`CASH_CHANGED`、
`POSITION_CHANGED`、`CORPORATE_ACTION_APPLIED`、`MARK_TO_MARKET`、
`KILL_SWITCH_ARMED`、`KILL_SWITCH_TRIGGERED`、`SESSION_CLOSED`、
`RECONCILIATION_PASSED`、`RECONCILIATION_FAILED`

每条事件携带：`event_id / sequence / event_time / market_time / run_id /
strategy_id / portfolio_id / symbol / payload / previous_hash / event_hash`。

## 3. 防篡改（诚实表述）

哈希链：每条事件带 `previous_hash` 与 `event_hash`。

| 测试 | 结果 |
| --- | --- |
| 正常追加后校验 | `valid = True` |
| **修改**任意一条事件 | `valid = False` |
| **删除**任意一条事件 | `valid = False` |
| 未知事件类型 | 直接抛 `LedgerError` |

**诚实声明（写在代码与校验输出里）**：这是
**tamper-evident（可检测篡改），不是 tamper-proof（不可篡改）**——能写该文件的人
可以重建整条链。不夸大为"不可变"。

写入用 `flush() + fsync()`，且**先落盘再推进内存状态**，避免崩溃时账本认为自己
记录了实际没记录的东西。

## 4. 恢复测试结果

| 测试 | 结果 |
| --- | --- |
| 重放重建现金与持仓 | ✅ 与运行中 Broker 完全一致 |
| 重放后对账 | ✅ `passed = True` |
| **对账能发现分歧** | ✅ 人为绕过账本改现金后 `passed = False`，并指出 "cash mismatch" |
| **断链拒绝恢复** | ✅ 抛 `RecoveryRefused` |
| Kill Switch 状态跨重启存活 | ✅ |
| T+1 结算状态跨重启存活 | ✅ `sellable` 正确恢复 |

## 5. 两个关键的"拒绝"

**恢复拒绝断链账本。** 从被编辑或截断的历史重建，会得到**有信心但无出处**的数字。
因此 `recover()` 默认 `require_valid_chain=True`，校验失败直接抛异常。

**对账失败是事故，不是舍入。** 若运行中状态与重放结果不一致，说明要么有动作绕过了
账本，要么重放是错的——两者都需要人介入。
