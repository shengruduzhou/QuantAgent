## 2. 恢复路径选择

三个候选：revert 掉 revert、cherry-pick 五个提交、重建等价补丁。

**选择：revert 掉 revert（`git revert 02e6942`）。**

判据是先量出来的，不是猜的：

```
git diff --stat 02e6942^ 02e6942   →  57 files changed, 12374 deletions(-)
git diff --stat 02e6942  b9a93e9   →  57 files changed, 12374 insertions(+)
```

**完全对称**。且 `02e6942` 只有一个父提交（非 merge commit），revert 无需 `-m`。

因此这条路径：
- 只产生**一个**可审查提交；
- 无需 cherry-pick 的冲突解决（那会引入人为差异）；
- 不重建补丁（重建的补丁可能与已评审内容悄悄不同）。

**未选择直接合并旧分支**：旧分支已落后于 main，且其内容已经过一轮"合并—回滚"，
再合并会产生令人困惑的历史。
