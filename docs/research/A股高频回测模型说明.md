## 1. 保真度是约束，不是选项

模拟器由 `FidelityDecision` 构造，而该决定**由数据推导**，策略作者无法自选。
每个成交模型在运行前断言自己需要的 claim；数据不支持就**抛异常**，不做静默降级。

静默降级正是"Level-B 结果在报告里被写成 Level-A"的成因，因此设计上不留这条路径。

| 等级 | 成交模型 | 可宣称 | `queue_position_shares` |
| --- | --- | --- | --- |
| Level A | 逐笔委托回放 | 排队位置、订单老化、前方撤单、价格-时间优先级 | 有值 |
| Level B | 快照回放 | 可见深度、深度耗尽、近似部分成交 | **恒为 None** |
| Level C | tick 回放 | 跨价成交、延迟、成交量参与 | None |
| Level D | bar 模拟 | 仅 bar 收盘成交 | None |
| `NOT_SIMULATABLE` | 拒绝构造 | 无 | — |

**本仓库当前数据的判定 = Level C**，附降级说明"3 秒聚合，桶内顺序与单笔规模不可观测"。

## 2. A 股规则（含来源与生效日）

规则会变。把旧值硬编码等于回测一个已不存在的市场，因此每个常量带来源与生效日，
查询函数接受交易日参数。

| 科创板 | ±20% | ±20% |

### 2.2 新股无涨跌幅窗口

- 沪深主板：**上市前 5 个交易日不设涨跌幅**，第 6 日起 ±10%。
  生效日 **2023-04-10**（全面注册制）。
  来源：<https://www.chinanews.com.cn/cj/2023/04-10/9986979.shtml>
- **2023-04-10 之前**的主板新股：首日 **+44% / −36%**（核准制）。
  模拟器按交易日自动切换，不会用今天的规则回测 2022 年。

## 3. 交易时段

| 时段 | 区间 | 说明 |
| --- | --- | --- |
| 开盘集合竞价 | 09:15–09:20 | 可撤单 |
| 集合竞价（不可撤） | 09:20–09:25 | |
| 静默 | 09:25–09:30 | |
| 连续竞价（早） | 09:30–**11:31** | 收盘价戳在 11:30:00，见下 |
| 午休 | 11:31–13:00 | |
| 连续竞价（午） | 13:00–14:57 | |
| 收盘集合竞价 | 14:57–**15:01** | 结果戳在 15:00:03，见下 |
| 科创板盘后固定价格 | 15:05–15:30 | 仅科创板 |
| 盘后不明记录 | 15:01–15:35 | `POST_CLOSE_UNCLASSIFIED` |

**两处边界为实测校正**（详见 `A股逐笔数据质量报告.md`）：

- 收盘集合竞价结果在**下一个快照**发布，时间戳 15:00:03。原半开区间
  `[14:57,15:00)` 排除它，导致全日恰好少算一笔集合竞价（600000.SH 少 486,400 股）。
- 早盘收盘聚合戳在 11:30:00–11:30:01，原 `[09:30,11:30)` 把它推进午休。

这两处是**对账推动的修正**，不是为了让检查通过而放松标准。

## 4. 成交模型细节

### 4.1 Level C（当前可用）

- 订单释放时刻 + 延迟假设后才可参与；
- 只在连续竞价时段成交（午休不成交，有测试）；
- 单笔订单最多吃掉观测成交量的 `participation_cap`（默认 10%）——没有这个上限，
  回测会成交出超过全日成交量的订单；
- 被动单遵守限价。

### 4.2 Level B

按档消耗可见深度，`queue_position_shares` **显式置 None**。

### 4.3 Level A

从委托流推排队位置：订单排在同价位已挂量之后，随前方成交与撤单前进，队列清空后
才成交。**这是唯一填充排队位置的等级**，因为只有这一级的数据让它可观测。

## 5. 与既有日频模拟器的关系

`quantagent.backtest.ashare_execution_simulator` 是**日频目标权重**模拟器
（Level D 范畴），本次**未改动**其行为，包括已促生产的 INC-E1 修复。

新增的 `microstructure_simulator` 是**事件驱动**的日内模拟器，二者互补而非替代。

## 6. 诚实限制

1. 当前唯一可用数据是 3 秒聚合 → **Level C 是上限**，无法做真正的高频回测；
2. 无 Level-2 → 排队位置、撤单领先量**不可得**；
3. 延迟假设是**参数**，不是从真实链路测得——本机没有可测的实时链路；
4. **不得**声称"HFT ready"：没有实测延迟与丢包，这个说法没有依据。
