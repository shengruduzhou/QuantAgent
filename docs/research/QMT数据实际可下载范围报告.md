## 3. 已实现的测量方法

`QmtGateway.probe_capability()` 对每个周期执行：

1. 请求**尽可能早**的起始日（默认 `19900101`）；
2. 记录**实际返回的第一行**日期；
3. 比较请求窗口与实际窗口 → `detect_truncation()`；
4. 窄于请求即判 `TRUNCATED`，并同时记录 requested 与 actual 两个区间。

这条判定是本模块的核心：**供应商在权限窗口外会"成功但少给"**，无报错。若只看
返回码，一年的基础档位会被误认为十年历史。

### 3.1 静默截断的识别（已有测试）

| 情形 | 判定 |
| --- | --- |
| 请求 1990 起，实际 2025 起 | `TRUNCATED` |
| 请求至 2026-07，实际至 2026-01 | `TRUNCATED` |
| 请求与实际一致 | 非截断 |
| 实际比请求更宽 | 非截断 |

### 3.2 其他必测项（方法已实现，数据未取得）

- 增量下载 vs 全量重建；
- 空成功响应（`EMPTY_UNVERIFIED`，见下）；
- 重复陈旧值填充；
- 不完整标的；
- **逐板块**覆盖（沪主板/深主板/创业板/科创板/北交所）。

## 4. 空响应的处理（关键）

`classify_empty()` 的默认是悲观的：

| 情形 | 判定 |
| --- | --- |
| 报错含权限关键词（权限/authoriz/VIP/lv2/未授权…） | `PERMISSION_DENIED` |
| 空，且**权限未确认** | `EMPTY_UNVERIFIED` |
| 空，且权限**已确认** | `EMPTY_VERIFIED` |

**`EMPTY_UNVERIFIED` 下游不得当作数据使用。** 这条规则直接决定了 ST 历史的处理
（见 `QMT历史ST权限与覆盖报告.md`）。
